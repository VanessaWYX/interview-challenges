## Scoring guide

- **Correctness**: 1 = broken, 3 = happy path works, 5 = happy path plus edge cases and tests.
- **Code clarity**: could a stranger read this in 5 minutes?
- **UI polish / API design**: FE = layout, states (loading/empty/error), accessibility. BE = sensible routes, status codes, validation.
- **Edge cases**: did you handle empty input, bad input, concurrency, slow networks?
- **Enjoyment**: did you lose track of time? Did you want to keep improving it?

## Reading the results

- Compare **average Correctness + Enjoyment** for FE rows vs BE rows.
- If FE enjoyment and polish are high but BE feels like a chore, lean front end.
- If you like both, or S1/S2 scored well and felt fun, full stack suits you.
- Time overruns matter too: repeatedly blowing the time box on one track tells you where you are slower.
- Re-do one challenge after 4 weeks to measure improvement.
