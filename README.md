# Interview Challenges: Frontend vs Full-Stack

A self-assessment pack. Do the challenges under a timer, score yourself, and see which kind of work you enjoy and do well.

## How to use

1. Pick a challenge folder and read its `README.md`.
2. Set a timer for the suggested time box. Stop when it ends, even if unfinished.
3. Build your solution in a `solution/` folder inside that challenge.
4. Score yourself with `SCORECARD.md` right after.
5. Commit one challenge per commit: `git commit -m "frontend/01: todo filter (52 min)"`.

## Stack

Use whatever you want to learn or already know (React/Vue/Svelte, Node/Python/Go, SQLite/Postgres). Keep the same stack across challenges so scores are comparable.

## Rules

- No copying full solutions. Docs and search are fine, as in a real interview.
- Write at least a few tests for backend work.
- Keep a `NOTES.md` per solution: what you'd do with more time, and what you got stuck on.

## Deciding

After 6 or more challenges, read the trends in `SCORECARD.md`. Pay attention to both scores and which challenges you were happy to keep polishing after the timer.
